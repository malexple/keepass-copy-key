# KeePassCopyKey

Минималистичный плагин для KeePass 2.x, который позволяет вручную выбрать
часть записей из открытой базы и перенести их в другую, независимую
установку KeePass — без сети и без облачных сервисов.

> Статус: в разработке.

## Что делает

- **Copy Keys...** (Tools → Copy Key): выбираете нужные записи из
  открытой базы через список с чекбоксами, опционально задаёте пароль,
  сохраняете в один файл `.kck`.
- **Load Keys...**: выбираете файл `.kck`, при необходимости вводите
  пароль — записи добавляются в текущую открытую базу. Нажмите Ctrl+S,
  чтобы сохранить их.

Файл `.kck` самодостаточен — его можно передать любым способом
(мессенджер, флешка, почта); пароль (если он есть) стоит передавать
отдельным каналом.

## Почему не через keepasshttp2?

Это отдельный проект с одной задачей, а не функция, встроенная в
`keepasshttp2` — никакого WebSocket-сервера, рукопожатий протокола и
постоянных identity-ключей. Только: выбрал → зашифровал → сохранил →
загрузил → расшифровал.

## Формат файла

```
4 байта   магическое число "KCK1"
1 байт    флаги: бит 0 = зашифровано
если зашифровано:
  16 байт   соль PBKDF2
  4 байта   число итераций PBKDF2 (по умолчанию 400 000)
  24 байта  nonce XSalsa20Poly1305
N байт    полезная нагрузка (открытый текст или шифротекст + 16-байтовый тег Poly1305)
```

Полезная нагрузка — плоский список записей с префиксом-счётчиком
(title/username/password/url/notes), каждая строка — с префиксом длины в
UTF-8. Никакого JSON и внешних форматов.

Пустой пароль — осознанный выбор, а не значение по умолчанию: диалог
экспорта не пропустит дальше, пока не введён пароль либо явно не отмечен
чекбокс "Do not encrypt".

## Криптография

- **Деривация ключа:** PBKDF2-HMAC-SHA256, 400 000 итераций, случайная
  16-байтовая соль на файл.
- **Шифрование:** XSalsa20Poly1305 (вендорится из `Chaos.NaCl`, тот же
  код, что скопирован из `Vendor/ChaosNaCl` проекта `keepasshttp2` — тот
  же примитив, но используется напрямую с ключом, полученным из пароля,
  без обмена ключами по X25519).

## Сборка

```powershell
dotnet build KeePassCopyKey.sln
```

При сборке `KeePassCopyKey` автоматически запускается набор тестов (см.
`Directory.Build.targets`) — отдельный `dotnet test` не нужен.

Указать другой путь к установке KeePass как compile-time референс:

```powershell
dotnet build KeePassCopyKey.sln -p:KeePassDir="C:\Path\To\Your\KeePass"
```

### Воспроизводимая сборка

В проекте включены `Deterministic`, `ContinuousIntegrationBuild` и
`PathMap` (см. `Directory.Build.props`) — сборка из чистого клона даёт
побайтово идентичную DLL независимо от машины и пути клонирования.
Проверка:

```powershell
Get-FileHash bin\Release\net48\KeePassCopyKey.dll
```

Эта гарантия дополнительно требует сборки против **одной и той же версии
KeePass.exe** на всех машинах (он используется только как
compile-time-референс, `Private=false`, но его версия всё равно влияет на
итоговые метаданные) — зафиксируйте конкретный релиз KeePass на всех
build-машинах, а не только путь `KeePassDir`.

## Структура проекта

```
KeePassCopyKey/          сам плагин
KeePassCopyKey.Tests/    тесты на xUnit — запускаются без установленного KeePass
```

`IO/KeyFile.cs` и `Crypto/KeyFileCrypto.cs` работают с простым типом
`KeyEntryRecord`, а не с `PwEntry` из KeePassLib — маппинг в `PwEntry`
есть только в `KeePassCopyKeyExt.cs` и `UI/EntrySelectionDialog.cs`. Это
позволяет тестировать формат файла и криптографию на любой машине.

## Установка

Скопируйте `KeePassCopyKey.dll` в папку `Plugins` KeePass и перезапустите
программу. Без упаковки в `.plgx` — плагин распространяется как обычная
скомпилированная DLL.
