# KeePassCopyKey

Минималистичный плагин для KeePass 2.x, который позволяет вручную выбрать
часть записей из открытой базы и перенести их в другую, независимую
установку KeePass — без сети и без облачных сервисов.

> Статус: в разработке.

## Про название

Проект и сборка называются `KeePassCopyKey`, но команды, которые видит
пользователь — **Export Keys** / **Import Keys** ("Экспортировать
ключи" / "Импортировать ключи"), а не "Copy"/"Load". В самом KeePass уже
есть команда **"Copy Entry (Encrypted)"** через буфер обмена между двумя
открытыми базами (Entry → Data Exchange) — если бы файловые команды
этого плагина тоже назывались "Copy", у знакомого со стандартным KeePass
пользователя возникла бы ложная ассоциация с той самой операцией через
буфер обмена, хотя механизм совсем другой. "Export"/"Import" повторяет
терминологию, которую KeePass уже использует для файловых операций
(File → Export, File → Import, Entry → Data Exchange → Export Entry) —
это ложится на уже знакомую пользователю модель. Само название проекта
осталось `KeePassCopyKey` по практическим причинам (переименование
задело бы `Directory.Build.props`, `.sln`, `InternalsVisibleTo` в
`AssemblyInfo.cs`, все `using` и этот файл — без функциональной пользы)
— поменялись только видимые пользователю строки.

## Что делает

- **Export Keys...** (Tools → Copy Key, либо иконка экспорта на панели
  инструментов): выбираете записи из открытой базы через дерево с
  чекбоксами (повторяет реальную структуру групп), задаёте пароль
  (по умолчанию уже подставлен случайный, можно изменить), сохраняете в
  файл `.kck`.
- **Import Keys...** (Tools → Copy Key, либо иконка импорта на панели
  инструментов): выбираете файл `.kck`, вводите пароль — записи
  добавляются в текущую открытую базу. Нажмите Ctrl+S, чтобы сохранить
  их.

Файл `.kck` самодостаточен — его можно передать любым способом
(мессенджер, флешка, почта); пароль стоит передавать отдельным каналом.

## Формат файла

```
4 байта   магическое число "KCK4"
1 байт    версия формата (1)
16 байт   соль PBKDF2
4 байта   число итераций PBKDF2 (по умолчанию 400 000)
24 байта  nonce XSalsa20Poly1305
N байт    шифротекст + 16-байтовый тег Poly1305
```

Полезная нагрузка — плоский список записей с префиксом-счётчиком
(title/username/password/url/notes), каждая строка — с префиксом длины в
UTF-8. Никакого JSON и внешних форматов.

Шифрование включено всегда — варианта "сохранить без пароля" нет. Более
ранние версии формата пробовали это (необязательный чекбокс, тихая
автогенерация пароля-заглушки, режим "без пароля, но зашифровано") — и
каждый вариант оказался проблемным по своей причине, вся история — в
комментарии в начале `IO/KeyFile.cs`. Поле пароля в диалоге экспорта
сразу заполнено случайным значением, так что там всегда есть что
отправить; кнопка OK просто отказывается закрываться при пустом поле,
вместо того чтобы молча делать что-то за пользователя.

## Криптография

- **Деривация ключа:** PBKDF2-HMAC-SHA256, 400 000 итераций, случайная
  16-байтовая соль на файл.
- **Шифрование:** XSalsa20Poly1305 через вендоренный поднабор
  MIT-лицензированной библиотеки `Chaos.NaCl` (`Vendor/ChaosNaCl/` — см.
  `Vendor/ChaosNaCl/License.txt`), используется напрямую с ключом,
  полученным из пароля. Ноль внешних зависимостей — ни NuGet-пакетов, ни
  нативных DLL.

## Сборка

```powershell
dotnet build KeePassCopyKey.sln
```

При сборке `KeePassCopyKey` автоматически запускается набор тестов (см.
`Directory.Build.targets`) — отдельный `dotnet test` не нужен.

Указать другой путь к установке KeePass как compile-time референс:

```powershell
dotnet build KeePassCopyKey.sln -p:KeePassDir="C:\Path\To\Your\KeePass"
```

### Воспроизводимая сборка

В проекте включены `Deterministic`, `ContinuousIntegrationBuild` и
`PathMap` (см. `Directory.Build.props`) — сборка из чистого клона даёт
побайтово идентичную DLL независимо от машины и пути клонирования.
Проверка:

```powershell
Get-FileHash bin\Release\net48\KeePassCopyKey.dll
```

Эта гарантия дополнительно требует сборки против **одной и той же версии
KeePass.exe** на всех машинах (он используется только как
compile-time-референс, `Private=false`, но его версия всё равно влияет на
итоговые метаданные) — зафиксируйте конкретный релиз KeePass на всех
build-машинах, а не только путь `KeePassDir`.

## Структура проекта

```
KeePassCopyKey/          сам плагин
KeePassCopyKey.Tests/    тесты на xUnit — запускаются без установленного KeePass
```

`IO/KeyFile.cs` и `Crypto/KeyFileCrypto.cs` работают с простым типом
`KeyEntryRecord`, а не с `PwEntry` из KeePassLib — маппинг в `PwEntry`
есть только в `KeePassCopyKeyExt.cs` и `UI/EntrySelectionDialog.cs`. Это
позволяет тестировать формат файла и криптографию на любой машине.

`AssemblyInfo.cs` даёт `KeePassCopyKey.Tests` доступ к `internal`-типам
этой сборки через `InternalsVisibleTo` — `KeyFile`, `KeyFileCrypto` и
`KeyEntryRecord` являются деталями реализации, а не публичным API,
поэтому остаются `internal`, а не `public`.

## Установка

Скопируйте `KeePassCopyKey.dll` в папку `Plugins` KeePass и перезапустите
программу. Без упаковки в `.plgx` — плагин распространяется как обычная
скомпилированная DLL.
